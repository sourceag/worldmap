# 世界观构建工作台（WorldForge）
## 产品设计文档 v1.1

---

## 1. 产品概述

### 1.1 产品名称
**WorldForge**（世界熔炉）

### 1.2 一句话定义
为创作者设计的结构化世界观构建系统，以空间维度为锚点，整合时间线、社会结构与叙事逻辑，帮助作者构建逻辑自洽的虚构世界。

### 1.3 核心定位
- **不是**地图绘制工具（不追求美术表现）
- **不是**写作软件（不处理正文写作）
- **是**世界观设计的"工作台"——专注于世界的骨架结构、内在逻辑与一致性维护

### 1.4 目标用户
| 用户类型 | 核心场景 | 付费意愿 |
|---|---|---|
| 网文/轻小说作者 | 长篇连载的世界观管理 | 中 |
| 跑团 DM（TRPG） | 战役世界的快速构建与逻辑校验 | 中高 |
| 独立游戏叙事设计 | 世界观文档与游戏机制对齐 | 高 |
| 影视/动画概念设计前期 | 世界观圣经制作 | 高 |

### 1.5 核心价值主张
> "让你专注于创作世界，而不是记忆世界。"

## 2. 核心理念

### 2.1 四维世界观模型
世界由四个不可分割的维度构成，工具必须同时支持这四个维度的创建与关联：

```
┌─────────────────────────────────────────┐
│              世界观四维模型                │
├──────────┬──────────┬──────────┬────────┤
│  空间维   │  时间维   │  社会维   │ 叙事维  │
├──────────┼──────────┼──────────┼────────┤
│ 大陆     │ 纪元     │ 势力     │ 事件   │
│ 区域     │ 时代     │ 国家     │ 冲突   │
│ 地点     │ 时间点   │ 文化     │ 因果   │
│ 路线     │ 持续时间 │ 宗教     │ 线索   │
│ 地形     │          │ 经济体系 │ 故事线  │
│ 气候     │          │ 人物关系 │        │
└──────────┴──────────┴──────────┴────────┘
```

### 2.2 一致性第一原则
工具的核心价值不在于帮助用户"记录"设定，而在于帮助用户"发现矛盾"：
- 时间线冲突：A 事件发生时，相关势力是否已存在？
- 地理逻辑：两地距离与文中描述的行军/旅行时间是否匹配？
- 社会逻辑：某势力的经济基础是否支撑其军事规模？
- 因果逻辑：某事件的前提条件是否在之前发生过？

### 2.3 渐进式复杂度
创作者可以从任意维度开始，不必按顺序填写：
- 可以先画一个大致地理轮廓
- 可以先写几个关键历史事件
- 可以先定义几个核心势力
- 工具帮助逐步完善并建立关联

## 4. 功能模块详细设计

### 4.1 空间系统（Geography）

#### 4.1.1 地图编辑器
**定位**：结构化地理数据的输入界面，非美术绘图工具

**功能描述**：
- **底图绘制**：支持简单的区域划分（多边形绘制），不追求精确地理特征
- **层级结构**：世界 → 大陆 → 区域 → 地点，树形管理
- **地图层管理**：
  - 政治边界层（势力范围）
  - 地形层（山脉、河流、森林——用简单图标表示）
  - 交通层（道路、航线）
  - 资源层（矿场、农田）
  - 可叠加显示/隐藏
- **比例尺设定**：定义地图上 1 像素 = 现实多少公里，用于后续距离计算
- **距离测量**：两点之间自动计算距离，支持"旅行时间估算"（考虑地形、交通方式）

**交互设计**：
- 左侧：地理要素树形列表
- 中间：画布（支持缩放、拖拽）
- 右侧：选中要素的属性面板

#### 4.1.2 地点详情
每个地点包含：
- 名称（支持多语言/别名）
- 所属区域
- 地点类型（城市、村庄、要塞、遗迹、自然景观...）
- 人口规模（可选）
- 特产/资源
- 重要建筑/地标
- 描述文本
- **关联入口**：
  - 哪些势力控制这里？
  - 哪些事件发生在这里？
  - 哪些人物居住/出身于此？

#### 4.1.3 区域/大陆模板
提供预设结构快速创建：
- 奇幻大陆：中央大陆 + 四方国度
- 群岛世界：多个岛屿群
- 单一城市：都市题材
- 星际文明：多个星球/星系

---

### 4.2 时间系统（Chronology）

#### 4.2.1 时间线编辑器
**核心功能**：
- **多纪元管理**：支持纪元嵌套（如"第三纪元 → 星火时代 → 历 342 年"）
- **事件卡片**：
  - 事件名称
  - 时间点/时间段
  - 事件类型（战争、灾难、发现、建国...）
  - 描述
  - 参与方（关联势力/人物）
  - 发生地（关联地点）
- **时间线视图**：横向时间轴，事件按时间排列，支持缩放
- **因果链**：事件 A → 导致 → 事件 B，可视化因果关系网

#### 4.2.2 时间-地图联动
**这是核心差异化功能**：
- 时间滑块拖动时，地图上的势力范围、控制区域随时间变化
- 可以"播放"历史演变动画
- 查看某一时间点的世界快照

#### 4.2.3 时间一致性校验
自动检测：
- 事件时间冲突（两件事发生在同一时间但参与方不可能同时在场）
- 因果倒置（结果发生在原因之前）
- 势力存续时间外的事件参与

---

### 4.3 社会系统（Society）

#### 4.3.1 势力管理
**势力属性**：
- 名称、类型（国家、教会、商会、秘密组织...）
- 存续时间（起始事件 → 终结事件）
- 意识形态/信仰
- 控制区域（关联地理）
- 军事力量（规模、兵种）
- 经济基础（资源、贸易）
- 外交关系（与其他势力的关系类型）

**势力关系图**：
- 节点：势力
- 边：关系类型（同盟、敌对、附属、贸易...）
- 支持按时间筛选查看不同时期的关系状态

#### 4.3.2 人物关系
**人物卡片**：
- 姓名、称号
- 生卒年（关联时间线）
- 所属势力
- 出身地
- 关键事件参与
- 人物关系（父子、师徒、敌对...）

**人物关系图**：
- 可视化人物关系网络
- 支持按势力、地域、事件筛选

#### 4.3.3 文化体系
**文化属性**：
- 语言/文字
- 宗教信仰
- 社会结构（阶级、种姓）
- 习俗/节日
- 禁忌/律法
- 科技水平

---

### 4.4 一致性引擎

#### 4.4.1 规则定义
用户可以自定义校验规则：
- "一个势力的军事规模不能超过其经济承载力"
- "某事件的参与方必须在事件发生时存在"
- "两地之间的旅行时间 = 距离 / 速度 × 地形系数"

#### 4.4.2 自动检测
系统实时扫描所有数据，发现潜在矛盾时：
- 标记矛盾点
- 给出矛盾描述
- 建议修复方向（不自动修改，由用户决定）

#### 4.4.3 矛盾面板
集中展示所有检测到的问题：
- 按严重程度排序
- 按维度分类（时间、空间、社会、叙事）
- 支持标记为"已知/有意为之"

### 4.5 插件系统（Plugin System）

#### 4.5.1 设计理念
插件系统是 WorldForge 与外部工具联通的桥梁。采用**本地事件驱动 + 文件监听**模式，无需网络服务即可工作，保证数据隐私和离线可用。

#### 4.5.2 插件类型

**事件监听器（Event Listener）**
- 监听 WorldForge 内部数据变更事件
- 当地点、势力、事件等实体被创建/修改/删除时触发
- 插件可响应事件并执行自定义逻辑

**数据导出器（Data Exporter）**
- 将 WorldForge 数据转换为外部格式
- 内置导出器：Markdown、JSON、YAML
- 插件可注册自定义导出格式

**数据导入器（Data Importer）**
- 从外部格式导入数据到 WorldForge
- 内置导入器：JSON、CSV
- 插件可注册自定义导入格式

**校验规则插件（Validator Plugin）**
- 扩展一致性引擎的校验能力
- 用户可编写自定义规则（JavaScript 函数）
- 规则接收世界数据，返回问题列表

**同步适配器（Sync Adapter）**
- 与外部写作软件双向同步
- 通过文件系统监听实现实时联动
- 适配器负责格式转换和冲突处理

#### 4.5.3 插件注册机制

```typescript
// 插件清单文件（plugin.json）
{
  "id": "obsidian-sync",
  "name": "Obsidian 同步",
  "version": "1.0.0",
  "type": "sync-adapter",
  "entry": "dist/index.js",
  "permissions": ["read:locations", "read:factions", "write:events"],
  "config": {
    "vaultPath": "~/Documents/MyVault",
    "syncInterval": 30
  }
}
```

#### 4.5.4 核心 API 接口

```typescript
// WorldForge 暴露给插件的 API
interface WorldForgeAPI {
  // 数据访问
  getWorld(): World;
  getEntity(type: string, id: string): Entity;
  queryEntities(filter: QueryFilter): Entity[];
  
  // 事件订阅
  on(event: 'entity:created' | 'entity:updated' | 'entity:deleted', handler: EventHandler): void;
  off(event: string, handler: EventHandler): void;
  
  // 导出
  registerExporter(format: string, exporter: ExporterPlugin): void;
  export(format: string, options: ExportOptions): Promise<Buffer>;
  
  // 导入
  registerImporter(format: string, importer: ImporterPlugin): void;
  import(format: string, data: Buffer, options: ImportOptions): Promise<ImportResult>;
  
  // 校验
  registerValidator(name: string, validator: ValidatorPlugin): void;
  
  // 文件系统（用于同步适配器）
  watchFile(path: string, callback: FileWatcherCallback): void;
  writeFile(path: string, content: string): Promise<void>;
  readFile(path: string): Promise<string>;
}
```

#### 4.5.5 内置插件

**Markdown 导出器**
- 将世界观导出为 Markdown 文档
- 支持 Obsidian 双向链接语法（`[[地点名]]`）
- 可自定义模板（选择导出哪些维度、层级结构）

**JSON/YAML 导出器**
- 完整数据导出，用于备份和迁移
- 支持按实体类型筛选导出

**Obsidian 同步适配器（V1 优先支持）**
- 监听 WorldForge 数据变更
- 将实体自动生成为 Obsidian 笔记（每个地点/势力/人物一个 .md 文件）
- 支持反向同步：在 Obsidian 中编辑笔记后，WorldForge 读取更新
- 双向链接自动关联

**Notion 同步适配器（V1 基础支持）**
- 通过 Notion API 导出世界观为数据库页面
- 需要用户提供 Notion API Key
- 单向同步（WorldForge → Notion）

**CSV 导入器**
- 从 CSV 文件批量导入地点/人物数据
- 支持字段映射配置

**典型使用场景：**

1. **作者在 WorldForge 中创建了一个新地点"银月城"**
   - Obsidian 插件监听到 `entity:created` 事件
   - 自动生成 `银月城.md` 笔记，包含地点属性、关联势力、相关事件
   - 笔记中使用 `[[势力名]]` 建立双向链接

2. **作者在 Obsidian 中更新了地点描述**
   - Obsidian 插件通过文件监听检测到文件变更
   - 解析更新内容，调用 WorldForge API 更新对应实体
   - WorldForge 内部数据同步更新，触发其他关联插件

3. **作者想将世界观导出到 Notion 分享给编辑**
   - Notion 插件将实体转换为 Notion 数据库页面
   - 每个实体类型对应一个数据库（地点库、势力库、人物库）
   - 数据库之间通过 Relation 字段建立关联

### 5.2 实体属性定义

#### World（世界）

## 7. 技术架构

### 7.1 技术选型

| 层级 | 技术方案 | 选择理由 |
|---|---|---|
| **前端框架** | React 18 + TypeScript | 生态成熟，类型安全 |
| **状态管理** | Zustand | 轻量，适合复杂嵌套数据 |
| **地图渲染** | 自研 Canvas 渲染 | 轻量，定制灵活，无需引入 Mapbox |
| **关系图** | React Flow | 现成组件，节点可定制 |
| **时间线** | 自研 | 需要与地图联动，无现成方案 |
| **数据持久化** | IndexedDB（本地）/ PostgreSQL（云端） | 本地优先，后续扩展云端 |
| **桌面端** | Tauri (Rust) | 比 Electron 轻量 10 倍 |
| **导出** | jsPDF + 自定义模板 | 简单可靠 |

### 7.2 架构原则
1. **本地优先**：所有数据默认存储在本地，保证隐私和离线可用
2. **离线优先**：不依赖网络即可使用全部功能
3. **可扩展**：预留云端同步、协作的接口

### 7.3 数据流

└─────────────┘     └─────────────┘     └─────────────┘

- [ ] 时间系统：纪元 → 时代 → 事件的层级创建与时间线视图
